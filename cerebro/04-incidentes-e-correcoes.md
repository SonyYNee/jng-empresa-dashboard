# Incidentes, causas e correções

Os episódios anteriores à criação do Git organizado são reconstruídos a partir das solicitações e do histórico disponível. O código e os commits mais recentes são a evidência verificável das correções posteriores.

| Episódio                             | Problema e decisão                                                                                                                                                                                                                     |
| ------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Primeira conexão Vertra              | Não havia endpoint confirmado. A tentativa inicial ficou incompleta. Mais tarde a documentação oficial e a API foram identificadas. A memória antiga sobre “sem conexão” está superada.                                                |
| Quilometragem                        | Cadastro não aceitava acima de 50 mil. Corrigido para aceitar valores maiores e entradas brasileiras; existe teste específico.                                                                                                         |
| Exclusões ausentes                   | Usuário pediu exclusão de veículo e, depois, de rota. Não retirar esses fluxos ao reorganizar cards.                                                                                                                                   |
| Previsão de manutenção               | Adicionado total previsto por mês/ano, separado do realizado. Teste evita misturar agendamento com despesa efetiva.                                                                                                                    |
| Rotas confusas                       | Cards e endereços foram refinados; coordenadas não devem aparecer como texto de endereço.                                                                                                                                              |
| Mini mapa incorreto                  | Mapas incorporados mostraram visão mundial/rota errada. Houve discussão de chave Google, mas o usuário decidiu retirar a integração visual.                                                                                            |
| Distância automática                 | Usuário exigiu solução sem custos. OSRM/OpenStreetMap adotado, com alternativa manual e limitações de serviço público.                                                                                                                 |
| Mensagem “rota salva” e refinamentos | Relatos de pequenos erros visuais motivaram revisão de alertas, espaçamentos e estados. Não há prova de auditoria visual exaustiva em todos os dispositivos.                                                                           |
| Eventos com título vertical          | Layout espremia “Eventos” letra por letra. Houve pedido específico de correção após refinamento geral; preservar a largura mínima e comportamento responsivo.                                                                          |
| Atividades da equipe                 | Faltava rolagem interna. Usuário reiterou esse requisito.                                                                                                                                                                              |
| Fotos de marketing ruins             | Limites/recompressão antigos degradavam imagens. Upload de mídia passou a preservar bytes, com teste acima de 5 MB e suporte a vídeo parcial.                                                                                          |
| Enquadramento da frota               | Cortes e miniaturas pequenas prejudicavam a visualização. Usar imagem inteira no quadro e galeria temática.                                                                                                                            |
| Capas cortadas                       | “Cover” puro cortava o assunto; “contain” isolado ficou visualmente ruim. Composição aprovada combina imagem inteira à direita, preenchimento/blur e gradiente vinho à esquerda.                                                       |
| Transição dura                       | Bordas e trocas muito secas. Ajustadas para transições suaves e delicadas.                                                                                                                                                             |
| Viagens ausentes na landing          | Seletor interno precisava permitir rotas particulares. A publicação do pacote é independente da visibilidade pública da rota.                                                                                                          |
| WhatsApp com símbolos estranhos      | Mensagem e codificação foram ajustadas. Corrigidos também `\\n` literal e regex `\\D` indevidamente escapada no arquivo de orçamento.                                                                                                  |
| Orçamento perdia dados               | Formulário da rota passou a transportar origem/destino/data/passageiros para o wizard. Botão individual da rota vai direto ao WhatsApp.                                                                                                |
| Cópias em diretórios diferentes      | Landing foi encontrada em `Documents/JNG EMPRESAA/JNG EMPRESAA/site-comercial`, depois consolidada no projeto Desktop e organizada em `apps/landing`. A cópia antiga não é a fonte ativa.                                              |
| Scripts de deploy falsos/obsoletos   | Existiam domínio de API fictício, placeholders, seed com credenciais fixas e workflow antigo. Removidos antes da publicação real. Não restaurar do histórico como instruções atuais.                                                   |
| Credenciais versionadas              | `.env` e chave privada estavam rastreados. Foram retirados do índice, preservados localmente e ignorados. O histórico Git antigo ainda pode conter segredos; não presumir que a remoção do arquivo apaga o histórico.                  |
| Pool PostgreSQL                      | Adaptador criava um pool por consulta. Corrigido para um pool compartilhado, limite de cinco conexões, timeouts, transações e fechamento explícito.                                                                                    |
| SQL SQLite aplicado ao PostgreSQL    | Inicializadores removiam sem querer a semântica de `SERIAL` e não aguardavam operações. Corrigidos; teste PGlite cobre IDs, decimais e vínculos.                                                                                       |
| Contagem de usuários                 | PostgreSQL retornava `'0'`, que é truthy em JavaScript. Corrigido com `Number`, evitando erros de bootstrap.                                                                                                                           |
| Upload autenticado                   | `session()` passou a ser assíncrona, mas mídia não aguardava a Promise. Corrigido com `await`; teste usa sessão assíncrona.                                                                                                            |
| Banco antigo inacessível             | Endpoint do `.env` antigo recusou conexão e não estava no inventário atual. Criado novo PostgreSQL da JNG, com novos certificados e senha; não resetado o banco antigo.                                                                |
| Documentação Vertra divergente       | `/v1/users/@me` e rotas antigas de workspace retornaram erro. O painel atual usava `/v1/users/me`. Contratos foram conferidos no código público do painel; não adivinhar endpoints.                                                    |
| Primeira inicialização sem envs      | Criação das duas aplicações retornou sucesso, mas os processos iniciaram antes de receber as variáveis. Uma nova inicialização resolveu após confirmar as envs pela API.                                                               |
| ZIP Windows no Linux                 | Pacote inicial da landing continha barras invertidas tratadas como nomes de arquivos. `/healthz` funcionava e `/` retornava 404. Corrigida geração dos ZIPs com `/` explícito; páginas e assets foram conferidos após upload.          |
| JSON de evento muito grande          | Um evento tinha quase 20 MB de imagens em base64. Extraídas dez referências em oito arquivos únicos, sem recompressão. JSON caiu para cerca de 2 KB; hashes remotos foram comparados aos originais.                                    |
| Login: Invalid time value            | A interface sempre acrescentava `Z` ao timestamp, duplicando o fuso do PostgreSQL. Corrigido em `db0e93c`; teste cobre SQLite, ISO Z, offset e entradas inválidas. Arquivo remoto comparado integralmente ao local.                    |
| Senha mínima divergente              | Frontend exigia 12 e backend 6. Usuário pediu 4. `1637a4c` alinhou cadastro inicial, usuários e troca de senha; testes usam senhas de quatro caracteres e rejeitam três no cadastro. Não houve alteração automática das senhas salvas. |
